# 챗봇 룰 파일 — BA가 직접 보고 고치는 곳

챗봇이 SQL 초안을 만들 때 따르는 규칙은 전부 이 폴더의 CSV 파일 4개에 있습니다. **엑셀이나 메모장으로 열어 고치고 저장하면 됩니다.** Claude나 개발자 도움 없이 고칠 수 있게 만들었습니다.

| 파일 | 내용 | 주로 고치는 것 |
|---|---|---|
| `tables.csv` | 테이블별 업무 영역, 사용 허용 여부, 회원 키 종류, 메모 | 쓰면 안 되는 테이블을 `allowed=N`으로, 이유는 `excluded_reason`에 |
| `terms.csv` | 업무 용어와 그 계산 SQL (순매출, 푸시 가능 고객 등) | 정의가 맞으면 `confirmed_by`에 이름 기입. 틀리면 `definition`과 `sql` 수정 후 `version` +1 |
| `joins.csv` | 테이블을 잇는 키와 관계(1:N 등) | 새 조인 경로 추가, 관계 정정 |
| `checks.csv` | SQL 자동 검사 규칙 | 규칙 끄기(`enabled=N`), 차단/주의 수준 변경(`severity`), 새 패턴 추가 |

## 고친 뒤 확인하는 법

터미널에서 이 폴더로 이동한 뒤:

```bash
python3 check_rules.py validate
```

- 룰 파일 4개를 마스킹 데이터에 대 보고 결과를 `OK / WARN / FAIL`로 보여 줍니다.
- `FAIL`이 하나라도 있으면 챗봇에 반영하기 전에 고쳐야 합니다.
- `confirmed_by`가 비어 있는 용어는 `WARN`으로 표시됩니다. BA가 확인하고 이름을 적으면 사라집니다.
- 순매출(T01)은 정의를 바꾸면 대시보드 집계와 몇 칸이 일치하는지 바로 보여 줍니다.

SQL 한 개를 규칙으로 검사하려면:

```bash
python3 check_rules.py sql 내쿼리.sql --type report
```

`--type`은 `report`(반복 리포트), `push_target`(푸시 대상자), `adhoc`(일회성) 중 하나입니다.

## 규칙(checks.csv) 읽는 법

| 열 | 뜻 |
|---|---|
| `enabled` | Y면 적용, N이면 끔 |
| `severity` | `block`이면 BA 검토 전에 챗봇이 다시 작성, `warn`이면 BA 화면에 경고만 |
| `pattern` | SQL에서 찾을 글자 패턴(정규식). R01·R02·R04·R09는 전용 로직이라 패턴 수정이 효과 없음 |
| `applies_to` | `all`, `report`, `push_target` 중 어디에 적용할지 |
